## Knowledge Query and Manipulation Language

Knowledge Query and Manipulation Language (KQML) is an AI agent communication language that acts to transfer information in segments, so that agents can process those segments separately (Finin et al., 1994). To explain this further, a KQML message uses performatives such as “ask”, “tell”, “subscribe”, “advertise” and others to state the sender’s intentions, content and transport independently from each other (Finin et al., 1994, pp. 457-460). Performatives are "permissible speech acts" that the AI agents use to interact with each other (Finin et al., 1994, p. 456). The facilitator agents manage the requests of these performatives. The advantage from separating the performatives is that the agents written in different programming languages and running on different platforms can communicate. New performatives can be added without breaking the code of the existing agents. A disadvantage of KQML is that there have been different interpretations, designs and dialects of it, so it is not standardized (Singh, 1998, pp. 46-47). Method invocation in Python and Java works differently from KQML messages. Python programs have class instances that have their own state and methods that are defined by their class (Python Software Foundation, 2026). Python calls are direct, so they are faster and more straightforward than KQML messages. In Java, a program creates objects that interact by invoking each other’s methods (Oracle, no date). The program carries out its goals through these interactions. KQML agents can also decide whether they will comply with KQML requests (Singh, 1998, p. 40). In Java and Python, program calls are always obeyed.
